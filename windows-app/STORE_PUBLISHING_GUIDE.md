# Microsoft Store MSIX Publishing Guide

This guide is for publishing Twality GMark Pro 1.0 as a free Windows desktop app
through the Microsoft Store using MSIX. In this path, Microsoft re-signs the submitted
MSIX package, so you do not need to buy or manage a production code-signing certificate
for Store distribution.

Review the latest Partner Center screens before final submission, because Store
requirements can change.

## 1. Choose the Submission Path

Use the Microsoft Store MSIX submission path:

- Build the app with PyInstaller.
- Package the built desktop app as MSIX using MSIX Packaging Tool or a Windows
  Application Packaging Project.
- Use local or test signing only while validating the package on your own devices.
- Submit the MSIX or MSIX bundle in Partner Center.
- Let Microsoft Store handle production signing, hosting, installation, and updates.

Keep the existing Inno Setup installer only as an optional direct-download artifact.
The EXE/MSI Store path requires publisher signing and hosted installer URLs, so it is
not the preferred Store path for this app.

## 2. Metadata to Lock Before Packaging

These values become part of the Store identity and update chain. Be careful changing
them after the first published submission.

- Product name / Store reserved name: `Twality GMark Pro`
- Package display name: `Twality GMark Pro`
- Publisher display name: `Twality Digital Solutions LLP`
- Package identity name: use the exact identity assigned by Partner Center after
  reserving the app name.
- Package publisher: use the exact publisher distinguished name from Partner Center.
  It often looks like a `CN=...` value and must match the manifest.
- Version: use a four-part MSIX version such as `1.0.0.0`. Keep it aligned with
  `APP_VERSION = "1.0.0"` in `config.py`.
- Executable/application entry point: `TwalityGMark.exe`.
- Architecture: start with `x64`. Add `arm64` later only after building and testing on
  an Arm64 Python/runtime. Use `x86` only if all dependencies support 32-bit Windows.
- Package family name: generated from package identity and publisher. Do not invent it.
- Privacy policy URL: host the contents of `PRIVACY.md` on an official HTTPS page.
- Support URL: `https://www.twality.com`
- Category: choose the most accurate Partner Center category, likely Photo & video,
  Productivity, or Utilities.
- Pricing: Free.

## 3. Manifest Fields to Check

When creating the MSIX package, verify these manifest values before submission:

- `Identity Name`: exact Partner Center package identity.
- `Identity Publisher`: exact Partner Center publisher value.
- `Identity Version`: four-part version, for example `1.0.0.0`.
- `Properties DisplayName`: `Twality GMark Pro`.
- `Properties PublisherDisplayName`: `Twality Digital Solutions LLP`.
- `Properties Logo`: `Assets\StoreLogo.png`.
- `Applications Application Id`: stable app id such as `App`.
- `Applications Application Executable`: `TwalityGMark.exe`.
- `Applications Application EntryPoint`: desktop bridge/full-trust desktop entry point
  generated by the packaging tool.
- `uap:VisualElements DisplayName`: `Twality GMark Pro`.
- `uap:VisualElements Description`: concise description from `STORE_LISTING_DRAFT.md`.
- `uap:VisualElements Square44x44Logo`: `Assets\Square44x44Logo.png`.
- `uap:VisualElements Square150x150Logo`: `Assets\Square150x150Logo.png`.
- `uap:VisualElements BackgroundColor`: choose a solid brand color that works with the
  transparent logo.
- Capabilities: include only what the packaged desktop app needs. Internet access is
  expected for reverse geocoding and maps. Avoid broad file-system capabilities unless
  certification testing proves they are necessary.

## 5. Build the App

From `windows-app`:

```powershell
.\.venv\Scripts\Activate.ps1
.\build-windows.ps1 -TargetArch x64 -SkipInstaller
```

The build copies committed Store/MSIX image assets from `assets\store` into
`dist\TwalityGMark\Assets`. To regenerate those committed assets from `Logo.png`, run:

```powershell
.\build-windows.ps1 -TargetArch x64 -SkipInstaller -RegenerateStoreAssets
```

After regenerating, review and commit the updated PNG files under `assets\store`.

Expected output:

```text
dist\TwalityGMark\TwalityGMark.exe
```

PyInstaller does not create a universal Windows binary. Repeat the build on a matching
Windows runtime for each native target you plan to submit:

```powershell
.\build-windows.ps1 -TargetArch x64 -SkipInstaller
.\build-windows.ps1 -TargetArch arm64 -SkipInstaller
.\build-windows.ps1 -TargetArch x86 -SkipInstaller
```

Use the `x86` target only if all required Python packages provide 32-bit Windows
wheels.

## 6. Package as MSIX

Use one of these packaging approaches:

- MSIX Packaging Tool: capture/package `dist\TwalityGMark\TwalityGMark.exe` and
  the files beside it.
- Windows Application Packaging Project: add the packaged desktop executable as the
  application entry point and generate the MSIX/MSIX bundle from Visual Studio.

During local testing, sign with a local test certificate and install that certificate
on the test device. This is only for validation before upload. The Microsoft Store
will re-sign the package after submission.

## 7. Test the MSIX Locally

Verify:

- The package installs cleanly on a fresh Windows test profile.
- Start menu tile/icon and app name show `Twality GMark Pro`.
- Window title is `Twality GMark Pro`.
- Settings, logs, and cache files are written under the user's LocalAppData folder.
- Help > About shows the correct product/company/website.
- Help > Help Contents opens correctly.
- Preview First Image works.
- Batch processing creates stamped copies.
- JPEG metadata restore works when ExifTool is available on PATH.
- Reverse geocoding and map display behave correctly when internet access is available.

## 8. Create the Partner Center Submission

1. Sign in to Partner Center.
2. Create or select the Windows app product.
3. Reserve the name `Twality GMark Pro`.
4. Copy the package identity name and publisher value assigned by Partner Center into
   the MSIX manifest/package configuration.
5. Start a new submission.
6. Complete product properties, category, pricing, markets, age rating, and support
   details.
7. Add the privacy policy URL hosted on the Twality website.
8. Add Store listing metadata from `STORE_LISTING_DRAFT.md`.
9. Upload screenshots and required Store artwork.
10. Upload the MSIX or MSIX bundle on the Packages page.
11. Save the draft, run certification checks, and submit for certification.

## 9. Operational Notes

- Keep a copy of every submitted MSIX/MSIX bundle.
- Increment the four-part MSIX package version for every Store update.
- Keep `APP_VERSION`, MSIX version, release notes, and Store listing updates aligned.
- Do not change package identity or publisher after release unless you intentionally
  want a new Store identity/update path.
- Keep the privacy policy up to date as features change.
